# 上手测试清单 · 3 分钟（Day 14）

> 这份是**给第一次用的人**看的。它不解释这个软件怎么实现，只给任务。
> 目的只有一件事：**看他在哪一步停下来**。他停下的那一步，就是我的 bug。

## 给测试员（拿着这份清单的人）三句话

1. **只给任务，不给提示。** 他问「这个点哪」的时候，回答「你觉得应该点哪？先试试」。
2. **卡住就让他卡住。** 他不动了、来回扫屏、鼠标乱晃，就是数据；别急着指路。超过 30 秒再给提示，并记下「给了提示才做完」。
3. **要他说，不要他评。** 不问他「好不好看」，问他「你刚才在找什么」。

## 准备

- 设备：**优先用电脑**。手机打不开本地网页文件（zip 解开后在手机上点 html，iOS 和 Android 都不好使）；
  要真在手机上测，得先把页面挂到网上，本期还没做。想验手机宽度不用真手机，浏览器开发者工具里调宽度就行。
- ⚠️ **别只发 `index.html` 一个文件。** 页面是用**相对路径**引 `style.css`（样式）和
  `app.js`（逻辑）的 —— 只发一个文件过去，对方看到的是**没样式、点了没反应的白板**。
  那不是他笨、也不是真 bug，会白测一轮。
  （实测过：单独一个 `index.html` → 背景透明、字体掉回 Times New Roman、顶栏卡在 `0 / 0`、
  点「加一个示例」毫无反应。）
  → **把整个文件夹发过去**（已经打好一个 zip，见下），让他**自己想办法打开里面的 `index.html`**。
- **别把 README 一起发。** 那里面写着每个功能怎么用、自测怎么做 —— 等于把答案给了他，
  「他找不找得到」就测不出来了。所以 zip 里**只放能跑起来的六个文件**
  （`index.html` / `style.css` / `app.js` / `dashboard.html` / `dashboard.css` / `dashboard.js`）。
- **六个文件齐了的话，双击 `index.html` 就能用**（不需要装任何东西、不需要服务器）——
  这条也实测过：背景色正常、点「加一个示例」真的加出一条、零报错。
- 他打不开（不知道双击 / 不知道用什么打开）→ **这一步本身就是今天最重要的发现**，记下来。
- 计时：每条任务从「念完题目」开始掐表。

## 七条任务（念给他听，一条一条来）

| # | 念的题目（照念，别加词） | 这条在测什么 |
| --- | --- | --- |
| 1 | 「你先打开看看，然后告诉我这是个什么东西、你打算先点哪里。」 | 第一眼是否自解释 |
| 2 | 「加一个习惯，叫『每天喝够 8 杯水』。」 | 新增入口好不好找 |

## 收尾必问的三句（照着念）

1. 「**哪一步让你最犹豫？**」
2. 「如果这个软件只能用一句话跟别人介绍，你会怎么说？」
3. 「**有没有哪句话、哪个按钮让你误解了？**」

## 判定：什么才算「卡住」

不用主观感觉，按下面任一条打钩（打钩的那一步，就是要修的那一步）：

- [ ] 任务开始后 **15 秒** 内没有任何点击动作（只在看、只在滑）
- [ ] 点了一个**跟任务无关**的东西（点错功能）
- [ ] 中途问出「这是干嘛的？」「点在哪儿？」这类问题
- [ ] 做完了但**结果不是他要的**（例如以为补的是昨天、实际记成了今天）
- [ ] 完成后**说不出自己刚才做了什么**

> 规则：**同一步里，只要 1 个人卡住 = 待观察；2 个人卡住 = 今天要修。**
> 只测 1 个人的时候，卡住的那一步直接进「最小修复」候选，从摩擦最大的开始修**一个**。
