## ① 用户问题（约 40 秒）

> 「我自己属于**漏一天就彻底放弃**的那种人。打卡软件给我一个大数字『连续 32 天』，
> 断一天归零 —— 那一瞬间我就不想再打开它了。
> 而且我的待办散在便签、聊天记录和脑子里，一想到就焦虑。
>
> 所以我要解决的就 **两件事**：**漏一天之后我还会打开它**、**打开一屏就能看清今天做什么、还剩什么**。
> 这两句话就是我的验收标准 —— 我做的每一件事，都要能指向这两句里的一句。」

**指着屏幕说**：强度是「最近 7 天的完成率」，**漏一天只是往下走一点，永远不会变成 0**（没做过显示「—」，不显示 0%）。

## ③ 提示词改写（约 50 秒）—— **同一件事，两种说法**

**❌ 原来那么说（模糊，AI 只能脑补）：**

```
帮我做一个写数据的接口。
```

**✅ 改成那么说（一次就做对）：**

```
写 POST /api/habits（新建习惯）。
只做「接口 → 部署 → 写入读回」这三步，今天不接前端（前端接写排第 4 周）。
约束：同一个名字提交两次要挡住；所有报错用中文；读接口那边一个字都不许动。
```

**为什么这么改**（这是 Day 10 总结出来的一句话模板 —— **在哪儿 / 实际是什么 / 期望是什么 / 边界**）：

| 四样 | 上面那句里的对应 |
| --- | --- |
| **在哪儿** | `POST /api/habits`，项目里已经有的那个地址 |
| **期望是什么** | 能写进库、重名挡住、报错中文 |
| **边界（哪些不许动）** | 「今天不接前端」「读接口一个字不许动」 |

**效果**：那天一次做对，没返工。而且「同一个名字要挡住」这句逼出了一个更硬的答案——
**光在代码里『先查一遍再写』挡不住并发**（查询和写入之间有缝），真正挡住的是**数据库自己的唯一索引**。
所以最后做成了**两层**：应用层负责把话说好听（`409` + 中文），数据库负责**真的让重复写不进去**。

> 📌 **补一句我最想讲的**：改写里那句「**今天不接前端**」比技术细节更值钱。
> 因为只接「新增」、不接「勾选/删除」，页面会变成一个**能加不能删的半成品** ——
> 与其交一个半成品，不如**把边界说清楚**，让这一步停在一个完整的位置。

## ④ 验证方式（约 40 秒）—— 不靠「我试了一下」，靠**能重跑的证据**

| 要证明什么 | 拿什么证明 | 怎么复跑 |
| --- | --- | --- |
| **真实读写** | 读 → `count 6`；写一条 → **201**；再读 → `count 7`（新 id 在）；删掉 → 再读回到 **6 条、与写之前逐条一致** | `python verify/day21-write-test.py` |
| **公网可访问 + 无报错** | 真浏览器打开公网地址：标题「习惯养成规划板」、小标「云端数据库」、6 个习惯；控制台 error **0** / 页面异常 **0** / 失败请求 **0**，跨源接口请求 CORS 放行 | `python verify/edge_net.py "<公网地址>" verify/day21-net2.js` |
| **交付物一致** | 公网 11 个文件与本地 `dist/` **md5 逐个相同**；内部文档（README/PRD/契约/`.env`）公网**全 404** | `python verify/day21-public-consistency.py` |
| **重构没改坏东西** | 拆出 `db.js` 前后，对**同一个真库**发同一组请求，返回体**逐字节**一样 | Day 19：本地 41/41、公网 20/20 |

**收尾一句话**：

> 「我没法证明『这个东西好』，但我能证明**它现在是真的在跑**：
> 数据真的进出数据库、公网真的打得开、页面真的没报错——**三条都能现场重跑，跑不出来就是我说错了**。」
