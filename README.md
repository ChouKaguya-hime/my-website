**切换方式为什么选 hash 路由**：四条路都摆过，前三条被本项目的硬约束挡掉了，不是凭偏好挑的：

| 方案 | 结论 |
| --- | --- |
| 路由库（React Router 那一类） | ✗ 要跑构建；而 AC-1 是「双击 `index.html` 就能开」，T2 又禁止 ES Module → 连加载都加载不起来 |
| History API（`pushState`） | ✗ **`file://` 协议下浏览器直接抛 SecurityError**，等于放弃 AC-1 |
| 纯 JS 显示 / 隐藏，地址栏不动 | ✓ 能用，但地址栏永远不变：刷新回默认视图、收藏不到具体一屏、浏览器返回键退不回去（训练营给的降级方案，能不用就不用） |
| **hash 路由** | ✓ `file://` 和 `localhost` 都能用、零依赖（`hashchange` 是浏览器原生的）、**地址栏跟着变**、前进后退白拿 |

白拿的三个好处：**能收藏 / 能分享**到具体某一屏；**浏览器自带的前进 / 后退**立刻可用；
**深链接** —— 把 `#/habit/xxx` 直接贴进地址栏回车，一进来就是那个习惯的详情页。

**四种状态各自补齐**：看板和习惯详情**各有一套**完整的加载 / 正常 / 空 / 出错。
详情页的「空」是「这个习惯还一次都没完成过」，「出错」是「找不到这个习惯 / 读不出存储」——
这两种必须分开说，混成一句会让人以为记录丢了（守设计原则 1：不制造惩罚性反馈）。

今日页 `index.html` 只在顶栏加了一个「看板 ↗」的入口链接（跨文件跳转），**业务逻辑一行没动**。

⭐ **今天最值钱的两条**：

1. **第一次打开公网地址，第一个要确认的不是「它通不通」，是「它返回的是不是我刚部署的那一份」。**
   「通」有太多种可能——平台的默认页、上一个版本、别人的环境、CDN 缓存。身份不对，后面排查全是白费。
   所以判据没靠人记，而是**写进返回体**，每次打开都能复核（见 `api-contract.md` 第 2.5 节）。
2. **「`curl` 通了」不等于「浏览器能打开」。** 用默认域名时，浏览器第一次访问会先撞上腾讯云的
   一张「页面访问提示」中间页，要点「确定访问」才放行；而 `curl` 完全不受影响、直接拿到 200 和真内容。
   这两件事必须**分开验**——否则分不清自己撞上的是中间页、缓存，还是真部署错了。

### 怎么部署（Day 15 起）

```powershell
# 0) 前提：本机装了 CloudBase CLI，且已登录（登录会打开浏览器让你点「授权」，
#    不需要把任何密钥交给别人 —— 密钥红线见 AGENTS.md 与训练营附录 M）
$TCB = "C:\Users\LM\.workbuddy\binaries\node\workspace\node_modules\@cloudbase\cli\bin\cloudbase"

# 1) 部署云函数（cloudbaserc.json 里有同名函数时会问是否覆盖，答 y）
& $TCB fn deploy api-health -e <环境ID>

# 2) 建 / 更新公网路由（规则写在 cloudbaserc.json 的 gateway 里，不写 domain 就用环境默认域名）
& $TCB deploy --only gateway -e <环境ID>

# 3) 打包前端（只挑那 6 个页面文件）再上传
node scripts\stage-static.js
& $TCB hosting deploy dist -e <环境ID> --verify
```

环境 ID 记在被 gitignore 的 `.env` 里（`ENV_ID=`），不进仓库。

**Day 16** 给项目建好了**数据库**（CloudBase 上的 PostgreSQL 17）—— 第一次把数据从「浏览器本地」往「云端关系型表」上落：

- 新增 **`db/schema.sql`** —— 建表脚本，三张表，全部可重复执行（`CREATE TABLE IF NOT EXISTS`）：

  | 表 | 存什么 | 关键点 |
  | --- | --- | --- |
  | `habits` | 习惯定义（名称、频率、创建日期） | 只存「习惯**是什么**」，不存完成情况 |
  | `habit_records` | 打卡记录（哪天完成了哪个习惯） | **靠 `habit_id` 关联 `habits`** ★ |
  | `todos` | 待办（一句话、归属日期、是否完成） | 与习惯表**无外键关联**，是独立列表 |

- ⭐ **今天要回答的那个问题**：「你的两张表分别存什么？它们靠哪个字段关联？」
  答：PRD 里习惯的完成情况是一个**数组**（`habit.doneDates`），而关系型数据库一个格子只能放一个值 ——
  所以必须把它拆出来单独成表：`habits` 存习惯本身、`habit_records` 存「一行 = 一次打卡」，
  两张表靠 **`habit_records.habit_id` → `habits.id`** 这个外键关联。
  （待办是另一个独立列表、不跟习惯挂钩；它们在页面上并排出现靠的是「同一天」这个口径，不是字段关联。）
- 新增 **`db/seed.sql`** —— 种子数据：6 个习惯 + 17 条打卡 + 6 条待办。
  **幂等**：每条 `INSERT` 都带 `ON CONFLICT … DO NOTHING`，重复执行不报错、也不插重复
  （实测：连跑第 2、3 次都是 `Affected rows: 0`，三张表行数稳定在 6 / 17 / 6）。
- **每个字段都写了注释**（`COMMENT ON COLUMN`），类型选择也都有理由：日期用 `DATE` 不用字符串、
  布尔用原生 `BOOLEAN`、`habit_id` 上建**外键 + 级联删除**、`(habit_id, done_date)` 加**唯一约束**防重复打卡。

### 怎么在库里跑一遍（Day 16 起）

```powershell
$TCB = "C:\Users\LM\.workbuddy\binaries\node\workspace\node_modules\@cloudbase\cli\bin\cloudbase"
$E = "<环境ID>"

# 建表（可重复执行）
& $TCB db execute -e $E --sql "$(Get-Content db/schema.sql -Raw)"

# 灌种子（可重复执行）
& $TCB db execute -e $E --sql "$(Get-Content db/seed.sql -Raw)"

# 验证：三张表各有多少行
& $TCB db execute -e $E --sql "SELECT 'habits' AS tbl, count(*) AS rows FROM habits UNION ALL SELECT 'habit_records', count(*) FROM habit_records UNION ALL SELECT 'todos', count(*) FROM todos"
```

> ⚠️ **不要加 `--role postgres`**：本环境里的角色名不是 `postgres`，加了会报
> `role "postgres_..." does not exist`。用默认角色就能建表。

## 怎么跑起来

### 方式 A · 直接双击（最省事）

双击 `index.html` 就能用。**不需要任何服务器、依赖或构建步骤。**
这是 `TECH_DESIGN.md` 定下的技术路线，用来满足 PRD 的 AC-1（双击就能打开）。

### 方式 B · 起一个本地服务器（地址栏是 localhost）

⚠️ **本机的 `python` 命令用不了**（2026-09-22 实测）：PATH 里的 `python` 指向 Microsoft Store 的占位程序
`C:\Users\LM\AppData\Local\Microsoft\WindowsApps\python.exe`，敲下去**不报错也不启动服务**，直接静默退出。
改用 WorkBuddy 自带的 Python，在**项目目录**下打开 PowerShell 执行：

```powershell
C:\Users\LM\.workbuddy\binaries\python\versions\3.13.12\python.exe -m http.server 8000
```

看到 `Serving HTTP on 127.0.0.1 port 8000 ...` 就是起来了 —— **这行会一直占着窗口，不会回到提示符**。
然后浏览器打开：**http://localhost:8000**

- 想结束它：回到那个窗口按 `Ctrl + C`
- 如果提示端口被占用：先关掉旧的那个窗口，或把 `8000` 换成 `8001`
- 页面本身不发任何外部网络请求（AC-10），所以方式 A 和方式 B 效果一样

### 方式 C · 打开看板（Day 8 新增，Day 12 接入真实数据，Day 13 拆成三个视图）

浏览器打开：

- 起了本地服务器的话：**http://localhost:8000/dashboard.html**
- 或者直接双击 `dashboard.html`

看板和今日页**共用同一份数据**（见下一节）。看板里有**三个视图**，靠地址栏里 `#` 后面那一小段切换：

| 地址 | 视图 | 怎么去 |
| --- | --- | --- |
| `#/board` | 看板（默认） | 顶部导航的「看板」；或者把地址栏里的 `#…` 整段删掉 |
| `#/states` | 状态自查（四种状态并排） | 顶部导航的「状态自查」 |
| `#/habit/<id>` | 习惯详情（二级视图） | 点一张卡片的**名字**；回来点面包屑或「← 返回看板」 |

顶部那个「今日页 ↗」是**跳到另一个文件**（`index.html`），和上面这三个「同一个文件里换视图」不是一回事。

在看板上能做的事：

- **新建习惯** —— 习惯区标题右边的「＋ 新建习惯」
- **一句话加待办** —— 页面底部的输入框，打字按回车
- **勾选完成** —— 点卡片右上角的圆圈
- **删除** —— 习惯卡片底部的「删除」、待办行尾的「×」，都要再确认一次
- **筛选** —— 顶部那组「全部 / 未完成 / 已完成」：点一下，习惯区和待办区**一起**收敛。
  它只管「屏幕上显示哪几条」，**不动数据**；刷新或重开页面都回到「全部」

⚠️ **两个页面要用同一种方式打开**（要么都走 `localhost:8000`，要么都双击本地文件）。
用 `http://localhost:8000/index.html` 加的数据，双击打开 `dashboard.html` 是看不到的 ——
浏览器的本地存储是**按「来源」分开存的**，`localhost:8000` 和 `file://` 在浏览器眼里是两个不同的地方。

## 数据存在哪

存在浏览器自带的本地存储里，键名是 `habit-board/v1`（带版本号，以后字段变了能区分新旧数据）。

**今日页和主视图读写的是同一个键** —— 所以两个视图共用一份数据，
在任意一页加的习惯和待办，另一页刷新后都在。**不存在「看板的数据」和「今日页的数据」两份。**

- 关掉浏览器再打开，数据还在（AC-9）
- 换一个浏览器、或把文件挪到别的文件夹，数据不跟着走——这是本期接受的限制，见 `TECH_DESIGN.md` 第 7 节

## 快速自测（30 秒）

### 今日页（`index.html`）

1. 首次打开：应看到「还没有习惯，先加一个试试」加一个示例按钮（AC-2）
2. 点那个示例按钮 → 习惯出现在列表里（AC-8）
3. 点习惯右边的圆圈 → 这一行变成已完成，顶部计数和「本周强度」立刻跟着变，不用刷新（AC-4）
4. 在底部输入框打一句话按回车 → 立刻出现在待办最上面，输入框被清空（AC-7）
5. 点习惯名字 → 打开详情，点一个**过去**的日期格子能补勾、再点一下取消；点**未来**的格子没有反应（AC-11）
6. 给待办加一条，再点它行尾的 `×` → 先弹二次确认（说的是「待办」不是「习惯」）；
   点「取消」它还在，点「删除」才真的消失（Day 14 补的，AC-15）

### 主视图（`dashboard.html`）

7. 打开看板 → 应该能看到刚才在今日页加的习惯和待办（**这就是「两个视图一份数据」**，AC-14）
8. 点「＋ 新建习惯」，只填名称就保存 → 卡片立刻出现在末尾（AC-8）
9. 在底部输入框打一句话按回车 → 那条立刻插到待办最上面（AC-7）
10. 点卡片底部的「删除」→ 先弹确认；点「取消」它还在，点「删除」才真的消失（AC-12 / AC-15）
11. 回到今日页刷新 → 刚才在看板上加的、删的，都已经同步过去了（AC-14）
12. 点顶部的「未完成」→ 习惯区和待办区**同时**只剩今天还没做的；点「已完成」→ 只剩做过的；
    点「全部」→ 恢复完整、与刚打开时逐条相同（AC-16）
13. 点顶部导航的「状态自查」→ 地址栏变成 `#/states`，**一屏里能看到四种状态**（加载 / 正常 / 空 / 出错）；
    点「看板」回来 → 地址栏变回 `#/board`（Day 13）
14. 点一张卡片的**名字** → 进到习惯详情（地址栏是 `#/habit/<id>`，顶部有面包屑「看板 / 习惯详情」）；
    点「← 返回看板」或按**浏览器后退键**都能回来（Day 13）
15. 把地址栏改成 `dashboard.html#/habit/h_不存在` 回车 → 详情页显示「找不到这个习惯」，
    而不是一片空白（Day 13）
