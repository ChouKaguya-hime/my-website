# filter-check · 筛选交互检查

## 一、它检查什么（一句话）

**筛选这一个交互，在三件事上都不糊弄：**
**① 三种情况都对（有结果 / 无结果 / 清空恢复）；② 来回切筛选不改动任何数据；③ 键盘和读屏软件也能用。**

这句话是这个技能的边界：它只审「筛选」，不审习惯强度算法、不审增删流程、不审视觉风格。
把边界收窄是有意的 —— 一个技能什么都管，等于什么都没管，最后没人会用它。

## 二、什么时候用它

- 动了 `dashboard.html` / `dashboard.css` / `dashboard.js` 里**跟筛选有关**的任何一行之后
- 每次要交付「筛选」这个功能之前（对应 PRD 的 **AC-16**）
- 想确认筛选**没有把既有行为弄坏**时（勾选、新增、删除都还在正常跑）

## 三、检查清单（逐条过，一条都不许跳）

| 编号 | 检查什么 | 怎么算过 |
| --- | --- | --- |
| **F1** | **有结果** | 点「未完成」→ 习惯区和待办区**同时**只剩今天未完成的；点「已完成」→ 同时只剩今天已完成的。两边的条数与该条件下的真实数据一致，不多不少 |
| **F2** | **无结果** | 构造出会筛空的数据（今天一条都没完成 → 点「已完成」），两个区块**各出现一句非空的说明**，不是一片空白；说明里**不含**「连续 / 中断 / 归零 / 失败」（PRD AC-6） |
| **F3** | **清空恢复** | 点「全部」→ 列表恢复完整，且条目名称序列与**刚打开页面时逐条相同**（数量、顺序都比） |
| **F4** | **筛选不改数据** | 连着切「未完成 → 已完成 → 全部」，读 `localStorage['habit-board/v1']` 的**原始字符串**，切换前后逐字节相同 |
| **F5** | **两个区块同口径** | 一次点击**同时**作用在习惯区和待办区；不允许出现「只筛了一个区块」（PRD F5 划死了：不做两个各自为政的筛选器） |
| **F6** | **可访问性** | ① 三个按钮能被 Tab 依次走到，Enter / 空格能切换；② `aria-pressed` 与视觉选中态**一致**，且任何时刻只有一个是 `true`；③ 每次切换后，`aria-live` 区（`#filter-state`）的内容真的变了；④ 选中态按钮的**文字对比度 ≥ 4.5:1**（WCAG AA） |
| **F7** | **项目硬约束没被弄坏** | 全程**零外部网络请求**（AC-10）；渲染后的**页面文本**里「连续 / 中断 / 归零 / 失败」命中数为 **0**（AC-6）；控制台**无 JS 报错** |

> F6 和 F7 是「余力加练」那一层加进来的。
> 为什么值得加：**筛选是纯键盘可操作的东西**（一排按钮），这正是无障碍最容易做对、也最容易漏掉的地方 ——
> 漏掉的表现是「鼠标点得动，Tab 走不到」，而这种问题自己用鼠标测永远测不出来。

## 四、怎么跑

技能自带可执行脚本 `run-check.js`（就是上面 F1–F7 的逐条断言，跑真实浏览器）。

```bash
# ① 在项目目录下起一个本地服务（本机 python 是商店占位程序，要用内置那份的完整路径）
C:\Users\LM\.workbuddy\binaries\python\versions\3.13.12\python.exe -m http.server 8000

# ② 另开一个终端，在项目目录下跑检查
"C:\Users\LM\.workbuddy\binaries\node\versions\22.22.2\node.exe" skills\filter-check\run-check.js
```

- 脚本依赖 `playwright-core`（复用本机已装的那份，不进项目依赖，不影响页面的「零依赖」）
- **退出码 0 = 全过**，非 0 = 有 FAIL（具体哪条看打印）
- 结果同时写一份 `last-run.json` 到脚本同目录，供留档

## 五、判定的两条硬规矩

1. **不许只看「脚本退出码 0」就说过了。** 必须翻一遍输出里 F1–F7 每一组的实际数字
   （比如 F1 要看到「筛出 3 个 / 数据里确实有 3 个」，而不是只看到 PASS）。
   ——这条是项目 AGENTS.md「追加 2」要求的：写进结论的事实，要能指出核验动作。
2. **不许为了让检查过而放宽检查。** 检查项是验收标准（AC-16）的翻版，改它等于改验收标准，
   得走 PRD 第 3.2 节过审，不能在脚本里偷偷放水。

## 六、调用记录

每次真跑过，往同目录的 `usage-log.md` 追加一行：日期 / 触发原因 / 结果 / 证据文件。
**没写进 `usage-log.md` 的，不算调用过。**
