## 1. 它解决的是哪一步的问题

**不是「打卡之后」，是「打开之前」。**

现有产品已经把「打卡」本身做得不难了（今日页一屏看全、点一下就完成）。但**更前面的一步**没解决：

> 用户原话（2026-10-04）：
> 「懒人真正懒到了的地步，**第一步就会倒在打开网页上**」

这落在 **P1（坚持不下去）** 的入口那一半：不是坚持不了 30 天，是**连打开都懒得打开**。
所以这个提案的目标很窄 —— **让「打开」这件事本身有一点吸引力。**

## 2. 为什么「趣味闹钟」那类机制搬不过来

最初参照的是「趣味闹钟」（响了必须跳一段舞才能关掉）。**它搬不过来**，因为两者方向正好相反：

| | 趣味闹钟 | 我们的网页 |
| --- | --- | --- |
| 用户怎么进来 | 闹钟**自己响**，被动被拽进来 | 用户**自己输入网址**，主动进来 |
| 机制作用在 | **出口**：提高关闭成本 | **入口**：? |

**对「不进来的人」提高关闭成本 = 零作用。** 我们缺的是入口，不是出口。

要解决的问题因此写成一句话：**打开的那一刻，有没有东西在等你。**

## 3. 借鉴了谁（四类机制，2026-10 查证）

| 类型 | 代表 | 漏一天会怎样 | 和本项目的关系 |
| --- | --- | --- | --- |
| 成长派 | **Finch** / Habits Garden | 你出现它就长，漏了**不会死** | ✅ **唯一兼容的一条路** |
| 纯连胜 | Streaks / Duolingo | 计数归零、从头再数 | ❌ 违反设计原则 1 |
| 损失派 | Habitica / Forest | 角色掉血 / 树当场枯死 | ❌ 违反设计原则 1 |
| 社交派 | Habit Huddle / 组队打卡 | 队友看见你今天没来 | ⚠️ 本期用户只有自己一个人 |

**Finch 的具体做法**（可直接借鉴的点）：

- 完成目标 → 攒能量 → 小鸟出门冒险 → 带回一段故事和纪念品
- **「宠物实验室」**：把某个习惯绑定到一颗**蛋**上，每完成一次孵化进度 +1，
  **累计满 7 次**孵化，**随机**得到一只新宠物（有可能开出稀有的）
- 漏一天小鸟**不会死**，只是「今天没出门」；还提供「修复」和「暂停」
- 核心反馈来自**用户和ta自己的小鸟**，不是排行榜

> 一篇评测里那句话值得抄下来：
> 「传统效率工具有个容易被忽略的问题：**完成任务的收益往往太遥远，而放弃却只需要一瞬间。**」
> 成长派做的事，就是把奖励**挪到完成的那一刻**，并且**给下一次打开留一个未知**。

## 4. 设计

### 4.1 一句话

**每完成一次习惯，你的小苗就长一格。它不会死，只会等你。**

### 4.2 规则

| 什么时候 | 发生什么 |
| --- | --- |
| 完成任意一个习惯 | 小苗**长一格**（当天最多长一格） |
| 一天没喂 | 今天**没长** —— 不枯、不掉叶、不清空；页面只说「今天它自己待着」 |
| 一周攒满 7 格 | 顶端**开一朵花**，花色随机（4 种里随机 1 种） |
| 下周一 | 格子归零重新开始，**已经开过的花留在「花架」上**（历史成就，不消失） |

> ⚠️ 注意「**攒满 7 格**」和「连续 7 天」是**两件完全不同的事**：
> 前者中间空了几天照样能满（只是慢一点），后者空一天就没了。
> 这里选前者，是设计原则 1 的直接落点。

### 4.3 文案（趣味措辞对照）

| 别这么说（现有产品的通用说法） | 这里这么说 |
| --- | --- |
| 打卡 / 签到 | **喂它一口** / 给它浇水 |
| 已完成 | 今天又长了一片叶子 |
| 漏了一天（黑名单词见 PRD 7 节） | **今天它自己待着** |
| 连续 7 天 | **攒够 7 格了，去开一朵花** |
| 进度 3/7 | 这周喂了 3 口 |

**「花架」的历史**也一并换成趣味的说法：「你养开过 4 朵花」（不是「累计打卡 28 天」）。

## 5. 过第 3.2 节三条标准（逐条）

| 标准 | 结论 |
| --- | --- |
| **1. 能不能验证核心痛点** | **能，验的是 P1 的入口那一半**。P1 原话是「漏一天就觉得前功尽弃，然后彻底不管了」，通过标准是「**漏一天之后我还会打开它**」—— 小苗提供了「打开看一眼」的理由：**它今天长了没有、有没有开出新的花**。而且它把「漏一天」的后果降到最低（只是没长），正面回应 P1 |
| **2. 需要后端才能做的，本期一律砍** | **不需要后端**。全部逻辑是「本地存一个 0–7 的计数 + 一个花色」→ 落在浏览器本地存储（与现有数据同一个键、不新增存储键）。**Day 16 建好的 `habit_records` 表天然就是它的数据源**（一行 = 一次完成），将来接数据库时零改造 |
| **3. 违反三条设计原则的，一律砍** | **不违反**，见下一节逐条对齐 |

## 6. 与三条设计原则的对齐

| 设计原则 | 本提案怎么守 |
| --- | --- |
| **1. 漏一天不能有惩罚性反馈** | 小苗**不会死、不会枯、不会掉叶**；没喂就是「今天它自己待着」。文案避开 PRD 第 7 节的黑名单（「连续 / 中断 / 归零 / 失败」四个词一个不用），未完成的格子用**中性灰**不用红色 |
| **2. 一个入口看全** | 小苗**不新开页面**，就长在今日页顶部概览那一行的旁边（或看板顶上），**与习惯区和待办区同屏**。它是「一眼扫到」，不是「要去某个地方看」 |
| **3. 默认零配置** | **不需要用户配置任何东西**。不需要选植物种类、不需要设目标天数、不需要开关。默认就长着，不填任何东西也能用 |

## 7. 边界（明确不做，防止做成另一个东西）

- ❌ **不做社交**：没有好友、没有排行榜、没有互相浇水（本期用户只有一个人）
- ❌ **不做养成失败**：小苗不会死、不会枯、不会因为长期不管而消失 —— **这条是红线**
- ❌ **不做商店 / 货币 / 等级**：不做金币、不做购买、不做经验值（那是 Habitica 那一派）
- ❌ **不做多品种选择**：不给用户挑「你想养什么」（违反原则 3）；就一种，随机开花
- ❌ **不做推送 / 通知**：本期不做消息推送（`research.md` 第六节已砍）
- ❌ **不改现有页面结构**：只在今日页/看板加一块小区域，不动现有的习惯区、待办区、筛选
